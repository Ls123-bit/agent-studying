## 1. 总览

本项目是基于 Spring Boot 3.x + Spring AI + MyBatis-Plus 的企业级 AI Agent 平台（Java 多模块 Maven 工程），注解使用密度极高：557 个 Java 文件中共扫得 **73 种注解（按注解名去重）、1893 个真实使用点**；其中 `@NotNull` 存在 jakarta/jetbrains 两个 import 来源，拆分统计则为 74 项。另有 2 个已定义、暂未被业务代码使用的自定义注解（见第 13 章）。

各来源分布（合计 74 项）：

| 来源分类 | 注解数 | 代表注解 |
|---|---|---|
| JDK 内置（java.lang / java.io 等） | 7 | `@Override`、`@Deprecated`、`@FunctionalInterface`、`@Target`、`@Retention`、`@Serial` |
| Lombok | 10 | `@Data`、`@AllArgsConstructor`、`@Slf4j`、`@Builder`（含 `@Builder.Default`） |
| Spring Framework / Boot | 33 | `@Service`、`@Bean`、`@RestController`、`@ConfigurationProperties`、`@Transactional`（含习惯归入 Spring 用法的 `@Resource`、`@PostConstruct`、`@Nullable`） |
| Spring AI | 2 | `@Tool`、`@ToolParam` |
| Spring AI Alibaba | 1 | `@HookPositions` |
| MyBatis-Plus / MyBatis | 4 | `@TableName`、`@TableId`、`@TableField`、`@Mapper` |
| Jakarta Validation | 4 | `@Valid`、`@NotNull`、`@NotBlank`、`@NotEmpty` |
| Swagger / OpenAPI | 2 | `@Operation`、`@Schema` |

| Spring Data Neo4j | 4 | `@Node`、`@Id`、`@Query`、`@Param` |
| Kafka | 2 | `@KafkaListener`、`@EnableKafka` |
| AspectJ | 2 | `@Aspect`、`@Around` |
| JetBrains（IDE 静态检查） | 1 | `@NotNull`(jetbrains 版) |
| 项目自定义（已定义未使用） | 2 | `@RepeatExecuteLimit`、`@ServiceLock` |

几个值得注意的全局特征：

- **全项目 0 次 `@Autowired`**：依赖注入全部采用构造器注入（配合 Lombok `@RequiredArgsConstructor` / `@AllArgsConstructor`）或 `@Resource`，这是刻意保持的编码规约。
- **无 `@Test` 等测试注解**：仅 1 个 `src/test` 目录（milvus 演示模块），项目基本不含单元测试代码。
- **ORM 层完全走 MyBatis-Plus 注解**：`@TableName`/`@TableId`/`@TableField` 覆盖全部实体，无 JPA `@Entity` 痕迹。
- **自定义注解只有 2 个**，都围绕 Redisson 分布式锁能力构建，通过 Spring Boot 自动装配 + AOP 切面生效，设计相当克制。

    boolean result = lock.tryLock(lockName, timeUnit, waitTime);

        finally { lock.unlock(lockName); }
    }
        
}

## 13. 项目自定义注解深度解析

项目仅有 2 个自定义注解，均位于 Redisson 框架模块，围绕"分布式锁 + 幂等"构建，是整个框架层的核心设计。

### 13.1 @RepeatExecuteLimit —— 防重复提交（幂等）

**定义位置**：`nexus-agent-redisson-framework\nexus-agent-redisson-service-framework\super-agent-repeat-execute-limit-framework\src\main\java\org\javaup\repeatexecutelimit\annotion\RepeatExecuteLimit.java`

**元注解（元信息）**：

```java
@Target(value = {ElementType.TYPE, ElementType.METHOD})   // 可贴类或方法
@Retention(value = RetentionPolicy.RUNTIME)               // 运行期保留（反射可读）
public @interface RepeatExecuteLimit {
    String name() default "";                             // 锁名前缀，缺省用类名+方法名
    String[] keys();                                      // SpEL 表达式数组，从入参提取业务键
    long durationTime() default 0L;                       // 幂等窗口秒数，<=0 不生效
    String message() default "提交频繁，请稍后重试";        // 拦截时抛出的提示
}
```

**生效机制**：`RepeatExecuteLimitAutoConfiguration` 通过 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 注册为自动配置，声明 `RepeatExecuteLimitAspect` Bean（`@Aspect + @Order(-11)`）。切面用 `@Around("@annotation(repeatLimit)")` 拦截后执行"本地 ReentrantLock 快速去重 → Redisson 公平锁分布式互斥 → Redis 标记位 + durationTime 窗口"三级防护：窗口内重复请求直接抛 `SuperAgentFrameException(message)`。

**项目内当前使用点**：业务代码（nexus-agent-business）暂未直接标注该注解——它作为框架能力随 starter 自动装配，随时可贴。

### 13.2 @ServiceLock —— 分布式锁

**定义位置**：`nexus-agent-redisson-framework\nexus-agent-redisson-service-framework\super-agent-service-lock-framework\src\main\java\org\javaup\servicelock\annotion\ServiceLock.java`

**元注解（元信息）**：

```java
@Target(value = {ElementType.TYPE, ElementType.METHOD})
@Retention(value = RetentionPolicy.RUNTIME)
public @interface ServiceLock {
    LockType lockType() default LockType.Reentrant;       // 锁类型: Reentrant/Fair/Read/Write
    String name() default "";                             // 锁名前缀
    String[] keys();                                      // SpEL 业务键
    long waitTime() default 10;                           // 获取锁最长等待
    TimeUnit timeUnit() default TimeUnit.SECONDS;         // 时间单位
    LockTimeOutStrategy lockTimeoutStrategy() default LockTimeOutStrategy.FAIL; // 超时策略
    String customLockTimeoutStrategy() default "";        // 自定义超时处理方法名
}
```

**生效机制**：`ServiceLockAutoConfiguration` 注册 `ServiceLockInfoHandle`（锁名解析）、`ServiceLockFactory`（按 `LockType` 路由到 RedissonReentrantLocker / RedissonFairLocker / RedissonReadLocker / RedissonWriteLocker 四种实现）和 `ServiceLockAspect`（`@Aspect + @Order(-10)`）。切面拦截标注方法：解析 SpEL 生成锁名 → 按类型 tryLock(waitTime) → 拿到锁执行 `joinPoint.proceed()` 并在 finally 解锁；超时则按策略 FAIL（抛异常）/ 自定义方法名反射调用兜底。

**与 @Order 的配合**：幂等切面 -11 比锁切面 -10 更先执行，保证"先判重、再抢锁"的语义顺序。
