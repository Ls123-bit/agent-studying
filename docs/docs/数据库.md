# 数据库设计全景

> 本文档梳理 Nexus Agent（superagent-understanding）项目中所有数据库与存储组件：建库方式、索引设计、表/索引的字段构成与业务意义。
>
> 依据来源：`sql/Mysql/create_table_mysql.sql`、`sql/PostgresSql/create_table_postgres_sql.sql`、`nexus-agent-business-chat/src/main/resources/application.yaml`，以及 ES 索引初始化器与 Neo4j 投影服务源码。

## 一、存储组件总览

| 组件 | 库/索引 | 角色 | 定义位置 |
| :--- | :--- | :--- | :--- |
| MySQL | `nexus_agent`（utf8mb4） | 主业务库：对话归档、文档治理、知识路由、可观测追踪、Graph Checkpoint | `sql/Mysql/create_table_mysql.sql` |
| PostgreSQL + pgvector | `nexus_agent_pgvector` | 向量库：文档切块 embedding 存储与相似度检索 | `sql/PostgresSql/create_table_postgres_sql.sql` |
| Elasticsearch | `nexus-agent-document-keyword` / `nexus-agent-document-navigation` / `nexus-agent-knowledge-route` | 关键词检索、结构导航、知识路由元数据 | 三个 `*ElasticsearchIndexInitializer.java`，启动时 `@PostConstruct` 自动建索引 |
| Neo4j | `neo4j`（bolt://127.0.0.1:7687） | 文档结构图（Document/Section/Item），支持图结构问答 | `Neo4jDocumentStructureGraphProjectionService.java`，启动时自动建索引 |
| Redis | database 0 | 运行时协调：会话租约、分布式锁、防重复执行（不存业务表数据） | `application.yaml` + `nexus-agent-redisson-framework` |
| MinIO | bucket `nexus-agent-document` | 对象存储：原始文件 + 解析后纯文本 | `application.yaml`（`app.manage.minio`） |
| Kafka | 2 个 topic | 异步任务消息（非数据库，驱动文档解析/索引链路） | `application.yaml`（`app.manage.kafka`） |

### MySQL 通用建库与约定

```sql
CREATE DATABASE nexus_agent DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

全部业务表遵循同一套约定：

- **主键**：`id BIGINT`（雪花 ID，应用侧生成），**不使用数据库自增、不建外键约束**，表间关联由业务代码维护。
- **公共字段**（下文各表不再重复列出）：
  - `create_time DATETIME` — 创建时间；
  - `edit_time DATETIME` — 最后编辑时间（也用于增量扫描）；
  - `status TINYINT(1)` — 逻辑删除标记：`1` 正常、`0` 删除。
- **引擎/字符集**：`ENGINE=InnoDB`，`utf8mb4 / utf8mb4_unicode_ci`。
- **索引命名**：`uk_` 前缀 = 唯一键；`idx_` 前缀 = 普通二级索引。组合索引普遍是「业务定位字段 + status」的结构，兼顾查询与逻辑删除过滤。

## 二、MySQL 主业务库（22 张表）

按业务域分为四组：**对话域**、**文档治理域（RAG 入库链路）**、**知识路由域**、**可观测域**，外加 2 张框架表。

### 2.1 对话域

#### nexus_agent_chat_dialogue —— 业务对话归档主表

一次业务会话（conversation）一行，记录会话状态与当前锁定的问答文档。

| 字段 | 类型 | 业务意义 |
| :--- | :--- | :--- |
| dialogue_code | VARCHAR(64) | 业务会话编号，贯穿所有对话域表的外部标识 |
| dialogue_stage | TINYINT(1) | 会话阶段：`1` 空闲 / `2` 进行中 |
| chat_mode | TINYINT(1) | 问答模式：`1` 当前文档问答 / `2` 开放式提问 |
| selected_document_id | BIGINT | 当前会话显式锁定的提问文档 id（"当前文档问答"模式的目标） |
| selected_document_name | VARCHAR(255) | 锁定文档名称快照 |

| 索引 | 字段 | 设计意图 |
| :--- | :--- | :--- |
| idx_..._code_status | (dialogue_code, status) | 按会话号取有效会话，最高频入口 |
| idx_..._stage_status | (dialogue_stage, status) | 筛选"进行中"的会话（如恢复/巡检） |
| idx_..._edit_time | (edit_time) | 按时间排序、清理过期会话 |

#### nexus_agent_chat_exchange —— 业务对话轮次归档表

一问一答为一行，保存提问原文、回答正文、以及各环节快照（JSON）。

| 字段 | 类型 | 业务意义 |
| :--- | :--- | :--- |
| dialogue_code | VARCHAR(64) | 所属业务会话编号 |
| user_prompt | TEXT | 用户提问原文 |
| reply_content | LONGTEXT | 助手回答内容 |
| reasoning_note_list | JSON | 过程提示与思考片段（思维链快照） |
| source_snapshot_list | JSON | 引用来源快照（回答依据） |
| followup_suggestion_list | JSON | 推荐追问快照 |
| tool_trace_list | JSON | 工具使用轨迹快照 |
| debug_trace_json | JSON | 调试轨迹快照 |
| exchange_state | TINYINT(1) | 轮次状态：`1` 进行中 / `2` 已完成 / `3` 失败 / `4` 已停止 |
| finish_note | TEXT | 失败或终止说明 |
| first_token_latency_ms | BIGINT | 首包耗时（毫秒），流式体验指标 |
| total_latency_ms | BIGINT | 总耗时（毫秒） |

| 索引 | 字段 | 设计意图 |
| :--- | :--- | :--- |
| idx_..._dialogue_status | (dialogue_code, status) | 拉取某会话的有效轮次历史 |
| idx_..._state_status | (exchange_state, status) | 追踪"进行中"轮次（异步落库/补偿） |
| idx_..._create_time | (create_time) | 时间线扫描与统计 |

#### nexus_agent_chat_memory_summary —— 长期记忆摘要快照表

"长期摘要 + 最近原文窗口"压缩策略的落库点，一个会话只保留一份最新摘要。

| 字段 | 类型 | 业务意义 |
| :--- | :--- | :--- |
| dialogue_code | VARCHAR(64) | 所属会话编号（**唯一**，一会话一摘要） |
| covered_exchange_id | BIGINT | 长期摘要已覆盖到的最后一条 exchangeId（增量压缩的推进水位线） |
| covered_exchange_count | INT | 已覆盖的轮次数 |
| compression_count | INT | 累计压缩次数 |
| summary_version | INT | 摘要版本号（乐观控制/版本对比） |
| summary_text | LONGTEXT | 编排阶段直接使用的长期摘要文本 |
| summary_json | JSON | 摘要结构化 JSON |
| last_source_edit_time | DATETIME | 摘要覆盖源轮次的最后更新时间（判断摘要是否过期） |

| 索引 | 字段 | 设计意图 |
| :--- | :--- | :--- |
| uk_..._dialogue | (dialogue_code) UNIQUE | 保证一会话一行，天然幂等 upsert |
| idx_..._cover | (covered_exchange_id) | 按覆盖水位线查询/对账 |
| idx_..._edit_time | (edit_time) | 摘要刷新时间扫描 |

#### GRAPH_THREAD / GRAPH_CHECKPOINT —— Spring AI Alibaba Graph 框架表

由 Graph 框架自动维护，支撑 ReAct Agent 的 **Checkpoint 持久化与断点恢复**（多轮对话间恢复 Agent 状态）。

**GRAPH_THREAD（线程表）**

| 字段 | 业务意义 |
| :--- | :--- |
| thread_id | Graph 内部线程主键（UUID） |
| thread_name | 业务线程名，通常就是 conversationId |
| is_released | 线程是否已被释放 |

索引：`IDX_GRAPH_THREAD_NAME_RELEASED (thread_name, is_released)` UNIQUE —— 按业务会话号定位未释放的线程，防止重复建线程。

**GRAPH_CHECKPOINT（检查点表）**

| 字段 | 业务意义 |
| :--- | :--- |
| checkpoint_id | Checkpoint ID（UUID 主键） |
| thread_id | 关联线程 ID |
| node_id / next_node_id | 当前节点 / 下一节点（图执行位置） |
| state_data | JSON，序列化后的 Agent 完整状态 |
| saved_at | 保存时间 |

索引：`idx_graph_checkpoint_thread_saved (thread_id, saved_at)` —— 恢复时按线程取**最新**一份 checkpoint。

### 2.2 文档治理域（RAG 入库链路）

对应链路：**上传 → 解析 → 策略推荐/确认 → 切块（父子块）→ 向量化 → 入库**。

#### nexus_agent_document —— 文档表（域内核心主表）

| 字段 | 类型 | 业务意义 |
| :--- | :--- | :--- |
| document_name | VARCHAR(255) | 文档名称（展示名，可被初始化脚本改写） |
| original_file_name | VARCHAR(255) | 原始上传文件名 |
| file_type | TINYINT | 文件类型：`1` PDF / `2` DOC / `3` DOCX / `4` TXT / `5` MD / `6` HTML |
| mime_type | VARCHAR(128) | MIME 类型 |
| file_size | BIGINT | 文件大小（byte） |
| storage_type | TINYINT | 存储类型：`1` MinIO |
| bucket_name / object_name / object_url | VARCHAR | MinIO 定位三元组：bucket、对象 key、访问地址 |
| parse_status | TINYINT | 解析状态：`1` 待解析 / `2` 解析中 / `3` 成功 / `4` 失败 |
| strategy_status | TINYINT | 策略状态：`1` 待推荐 / `2` 已推荐 / `3` 已确认 / `4` 已失效 |
| index_status | TINYINT | 索引状态：`1` 待构建 / `2` 构建中 / `3` 成功 / `4` 失败 |
| char_count / token_count | INT | 解析后字符数 / token 估算数（体量评估） |
| structure_level | TINYINT | 结构化程度：`0` 未知 / `1` 低 / `2` 中 / `3` 高（决定推荐哪种切块策略） |
| content_quality_level | TINYINT | 内容质量：`0` 未知 / `1` 低 / `2` 中 / `3` 高（低质量时推荐追加大模型切块） |
| parse_text_path | VARCHAR(512) | 解析后纯文本在 MinIO 的存储路径 |
| parse_error_msg | VARCHAR(1000) | 解析失败原因 |
| knowledge_scope_code / knowledge_scope_name | VARCHAR | 业务知识域编码/名称（如 oa / crm / finance），知识路由第一层的挂靠点 |
| business_category | VARCHAR(128) | 业务分类（如 流程 / 规则 / 操作手册） |
| document_tags | VARCHAR(512) | 逗号分隔标签快照 |
| current_plan_id | BIGINT | 当前生效的策略方案 id |
| last_parse_task_id | BIGINT | 最近一次成功解析任务 id |
| structure_node_count | INT | 最近一次结构化解析生成的节点数 |
| last_index_task_id | BIGINT | 最近一次索引任务 id |

| 索引 | 字段 | 设计意图 |
| :--- | :--- | :--- |
| idx_object_name | (object_name) | 由 MinIO 对象反查文档 |
| idx_parse_status / idx_strategy_status / idx_index_status | 单列 | Kafka 消费者/调度扫描待处理文档 |
| idx_knowledge_scope_code | (knowledge_scope_code) | 按知识域圈定文档集合 |
| idx_current_plan_id | (current_plan_id) | 文档 ↔ 方案联查 |

#### nexus_agent_document_strategy_plan —— 文档策略方案表

一份文档可以有多版本切块方案；用户确认后执行。

| 字段 | 类型 | 业务意义 |
| :--- | :--- | :--- |
| document_id | BIGINT | 文档 id |
| plan_version | INT | 方案版本号（与 document_id 联合唯一） |
| plan_source | TINYINT | 方案来源：`1` 系统推荐 / `2` 用户调整 |
| plan_status | TINYINT | 方案状态：`1` 待确认 / `2` 已确认 / `3` 已执行 / `4` 已废弃 |
| strategy_count | TINYINT | 方案内策略数量 |
| strategy_snapshot | VARCHAR(255) | 策略快照（如 `1,2,3`，即策略类型 id 串） |
| recommend_reason | TEXT | 系统推荐原因（给用户看的解释） |
| adjust_note | VARCHAR(500) | 用户调整说明 |
| confirm_user_id / confirm_time | - | 确认人 / 确认时间（人工确认留痕） |

索引：`uk_document_version (document_id, plan_version)` UNIQUE —— 版本幂等；`idx_plan_status (plan_status)` —— 扫描待确认方案。

#### nexus_agent_document_strategy_step —— 文档策略步骤表

方案展开为可执行步骤；**父块流水线与子块流水线分开编排**。

| 字段 | 类型 | 业务意义 |
| :--- | :--- | :--- |
| plan_id / document_id | BIGINT | 方案 id / 文档 id |
| step_no | INT | 执行顺序 |
| pipeline_type | VARCHAR(16) | 流水线类型：`PARENT` 父块流水线 / `CHILD` 子块流水线 |
| strategy_type | TINYINT | 策略类型：`1` 基于文档结构切块 / `2` 递归分块 / `3` 语义分块 / `4` 大模型智能切块 |
| strategy_role | TINYINT | 策略角色：`1` 主策略 / `2` 优化 / `3` 兜底 / `4` 增强 |
| source_type | TINYINT | 来源：`1` 系统推荐 / `2` 用户新增 / `3` 用户保留 |
| execute_status | TINYINT | 执行状态：`1` 待执行 / `2` 执行中 / `3` 成功 / `4` 失败 / `5` 已跳过 |
| recommend_reason | VARCHAR(500) | 本步骤的推荐原因 |

索引：`uk_plan_pipeline_step_no (plan_id, pipeline_type, step_no)` UNIQUE —— 方案内两条流水线的步骤顺序各自唯一；`idx_document_id` / `idx_strategy_type` / `idx_pipeline_type` 支撑按文档、按策略类型的查询与统计。

#### nexus_agent_document_task —— 文档任务表

文档级异步任务（解析路由 / 构建索引）的执行主记录。

| 字段 | 类型 | 业务意义 |
| :--- | :--- | :--- |
| document_id / plan_id | BIGINT | 文档 id / 执行方案 id |
| task_type | TINYINT | 任务类型：`1` 解析路由 / `2` 构建索引 |
| task_status | TINYINT | 任务状态：`1` 新建 / `2` 进行中 / `3` 成功 / `4` 失败 / `5` 已取消 |
| current_stage | TINYINT | 当前阶段：`1` 文件上传 → `2` 内容解析 → `3` 策略路由 → `4` 策略确认 → `5` 切块执行 → `6` 切块后处理 → `7` 向量化 → `8` 入库完成（八阶段流水线水位线） |
| trigger_source | TINYINT | 触发来源：`1` 系统自动（Kafka）/ `2` 用户手动 |
| strategy_snapshot | VARCHAR(255) | 执行时策略快照（留痕，防止执行与方案不一致） |
| retry_count | INT | 重试次数 |
| start_time / finish_time / cost_millis | - | 起止时间与耗时 |
| error_code / error_msg | - | 错误码与信息 |
| ext_json | TEXT | 扩展信息 JSON |

索引：`idx_document_task (document_id, task_type)` —— 查某文档某类任务的历史；`idx_task_status` —— 扫描待处理/进行中任务；`idx_plan_id` —— 方案维度回溯任务。

#### nexus_agent_document_task_log —— 文档任务日志表

任务八阶段的逐事件审计日志（开始/完成/失败/推荐策略/用户调整/用户确认）。

| 字段 | 类型 | 业务意义 |
| :--- | :--- | :--- |
| task_id / document_id | BIGINT | 任务 id / 文档 id |
| stage_type | TINYINT | 阶段类型（同任务表八阶段枚举） |
| event_type | TINYINT | 事件类型：`1` 开始 / `2` 完成 / `3` 失败 / `4` 推荐策略 / `5` 用户调整 / `6` 用户确认 |
| log_level | TINYINT | 日志级别：`1` INFO / `2` WARN / `3` ERROR |
| operator_type / operator_id | - | 操作人类型（`1` 系统 / `2` 用户 / `3` 管理员）与 id（区分自动化与人工动作） |
| content / detail_json | - | 日志内容与明细 JSON |

索引：`idx_task_id` / `idx_document_id` / `idx_stage_type` —— 分别按任务、文档、阶段回放日志。

#### nexus_agent_document_structure_node —— 文档结构节点表

解析阶段产出的**文档结构树**（根 → 章节 → 步骤/列表项），是切块对齐与导航的基础，同时可投影到 Neo4j。

| 字段 | 类型 | 业务意义 |
| :--- | :--- | :--- |
| document_id / parse_task_id | BIGINT | 文档 id / 解析任务 id |
| node_no | INT | 文档内稳定顺序号（与 parse_task_id 联合唯一） |
| node_type | TINYINT | 节点类型：`1` 文档根节点 / `2` 章节 / `3` 步骤 / `4` 列表项 |
| parent_node_id | BIGINT | 父节点 id（构成树） |
| prev_sibling_node_id / next_sibling_node_id | BIGINT | 前后同级节点 id（双向链表，支撑"上一节/下一节"导航） |
| depth | INT | 节点深度 |
| node_code | VARCHAR(128) | 节点编码（如 `1.2`、`第一章`、`4`） |
| title | VARCHAR(1000) | 节点标题 |
| anchor_text | VARCHAR(1000) | 供导航和锚点使用的短锚文本 |
| canonical_path | VARCHAR(1000) | 节点稳定路径（跨解析版本稳定的定位串） |
| section_path | VARCHAR(1000) | 兼容现有系统的章节路径文本 |
| content_text | LONGTEXT | 节点正文 |
| item_index | INT | 列表项/步骤项序号 |

索引：`uk_parse_task_node_no (parse_task_id, node_no)` UNIQUE —— 同一次解析内节点序号稳定可重放；`idx_document_id` / `idx_parse_task_id` —— 文档与解析任务两个维度；`idx_parent_node_id` —— 树的自顶向下遍历；`idx_node_type` —— 按类型筛选（如只取章节）。

#### nexus_agent_document_parent_block —— 文档父块表

Parent-Child 检索结构的"父块"层：检索命中子块后**提升到父块**作为最终证据，保住完整上下文。

| 字段 | 类型 | 业务意义 |
| :--- | :--- | :--- |
| document_id / task_id / plan_id | BIGINT | 文档 / 索引任务 / 方案 id |
| parent_no | INT | 父块序号（与 task_id 联合唯一） |
| source_type | TINYINT | 内容来源：`1` 原文切块 / `2` 后处理补全文本 |
| section_path / canonical_path | VARCHAR | 章节路径 / 结构节点稳定路径 |
| structure_node_id / structure_node_type | - | 关联的结构节点 id 与类型（父块 ↔ 结构树对齐） |
| item_index | INT | 列表项/步骤项序号 |
| parent_text | LONGTEXT | 父块完整内容（回答时注入的正文） |
| char_count / token_count | INT | 字符数 / token 数（父块证据预算控制，配置上限 2200 字符） |
| child_count | INT | 父块内部 child 数量 |
| start_chunk_no / end_chunk_no | INT | 父块映射到的第一个/最后一个 child 序号（父子映射区间） |

索引：`uk_task_parent_no (task_id, parent_no)` UNIQUE —— 同任务内父块序号幂等；`idx_document_id` / `idx_task_id` —— 文档与任务维度。

#### nexus_agent_document_chunk —— 文档切块表

向量化的最小单位（子块），检索召回的直接对象。

| 字段 | 类型 | 业务意义 |
| :--- | :--- | :--- |
| document_id / task_id / plan_id | BIGINT | 文档 / 索引任务 / 方案 id |
| parent_block_id | BIGINT | 所属父块 id（父子层级关系） |
| chunk_no | INT | 块序号（与 task_id 联合唯一） |

### nexus_agent_document_embedding —— 文档切块向量表

与 MySQL `nexus_agent_document_chunk` **一对一**：`id` 直接复用 MySQL chunk 主键，实现关系库与向量库的天然对齐。

| 字段 | 类型 | 业务意义 |
| :--- | :--- | :--- |
| id | BIGINT | 主键，**直接复用 MySQL chunk 主键**（跨库对齐键） |
| document_id / task_id / plan_id | BIGINT | 文档 / 索引任务 / 方案 id（与 chunk 表冗余一致，便于向量库内过滤） |
| parent_block_id | BIGINT | 所属父块 id（命中向量后可提升父块） |
| chunk_no | INTEGER | 切块序号 |
| source_type | SMALLINT | 内容来源：`1` 原文切块 / `2` 后处理补全文本 |
| section_path / canonical_path | VARCHAR(1000) | 章节路径 / 结构节点稳定路径（检索结果回显定位） |
| structure_node_id / structure_node_type | - | 关联结构节点 |
| item_index | INTEGER | 列表项/步骤项序号 |
| chunk_text | TEXT | 切块文本内容（向量检索后直接取文，免回查 MySQL） |
| char_count / token_count | INTEGER | 字符数 / token 数 |

| metadata_json | JSONB | 向量检索附带元数据（混合过滤） |
| embedding | VECTOR | **向量值**（未固定维度） |
| status | SMALLINT | `1` 正常 / `0` 删除 |

### 向量索引现状（重要设计决策）

当前只建了 **5 个 B-tree 标量索引**：

```sql
idx_nexus_agent_document_embedding_document_id     (document_id)
idx_nexus_agent_document_embedding_task_id         (task_id)
idx_nexus_agent_document_embedding_plan_id         (plan_id)
idx_nexus_agent_document_embedding_parent_block_id (parent_block_id)
idx_nexus_agent_document_embedding_status          (status)
```

- B-tree 索引用途：按文档/任务/方案/父块**删除与重建**（重建索引任务时按 task_id 清旧向量）、按文档过滤（"当前文档问答"模式下限定检索范围）、父块提升查询。
- `embedding` 字段**尚未建向量索引**：脚本注释明确说明——第一期为了兼容不同 embedding 模型的维度变化，使用**未固定维度的 VECTOR 类型**；后续固定模型与维度（如 1024/1536）后，可改为 `VECTOR(1024)` 并补充 **HNSW 或 IVF_FLAT** 向量索引。当前规模下靠全表精确扫描（KNN）换取维度灵活性。

## 五、Neo4j 结构图

MySQL 结构节点表投影为图，支持"章节目录、步骤定位、兄弟遍历"等图结构问答（配置 `app.manage.neo4j.enabled=true` 时启用，关闭则回退查 MySQL 结构节点表）。

### 图模型

**节点标签**

| 标签 | 来源 | 业务意义 |
| :--- | :--- | :--- |
| `Document` | 文档主表 | 一份文档的根入口（属性 documentId） |
| `Section` | 结构节点（章节类） | 章节，含 title/anchorText/sectionPath/contentText/normalizedTitle 等 |
| `Item` | 结构节点（步骤/列表项） | 步骤或列表项，含 itemIndex、sectionNodeId 等 |

**关系**

| 关系 | 方向 | 业务意义 |
| :--- | :--- | :--- |
| `HAS_SECTION` | Document → Section | 文档的一级章节 |
| `HAS_CHILD` | Section → Section | 章节嵌套（父子层级） |
| `HAS_ITEM` | Section → Item | 章节下的步骤/列表项 |
| `BELONGS_TO_DOCUMENT` | Section → Document | 反向归属（双向遍历） |
| `BELONGS_TO_SECTION` | Item → Section | 反向归属 |
| `NEXT_SIBLING` / `PREV_SIBLING` | Section↔Section、Item↔Item | 同级双向链表（"下一节"导航） |

## 六、Redis / MinIO / Kafka（运行时存储与消息）

### Redis（database 0）

不存业务表数据，承担三类运行时职责：

1. **会话租约**：`RedisLeaseManager`（acquire / renew / release），保证同一 conversationId 同一时刻只有一个实例在执行流式回答（`BusinessChatService` 中 claimConversationLease / renewLeaseOrStop / 释放租约），TTL + 续租实现故障自动接管。
2. **分布式锁**：`nexus-agent-redisson-framework` 提供可重入锁封装。
3. **防重复执行 / 服务租约**：Redisson 的 RepeatExecuteLimit、ServiceLease 框架组件。

### MinIO

对象存储，bucket `nexus-agent-document` 启动时自动创建：

- `rag/document/...` — 用户上传的原始文件（对应 `nexus_agent_document` 的 bucket_name/object_name/object_url 三元组）；
- `rag/parsed-text/...` — Tika 解析后的纯文本（对应 parse_text_path），便于切块与重建索引时免重复解析。

### Kafka（消息，驱动异步链路）

| Topic | 驱动的链路 | 落库表 |
| :--- | :--- | :--- |
| `nexus-agent-document-parse-route` | 上传后异步"解析 + 策略推荐" | document_task / task_log / structure_node / strategy_plan |
| `nexus-agent-document-index-build` | 确认策略后异步"切块 + 向量化 + 入库" | parent_block / chunk / embedding / ES 索引 |

## 七、索引设计模式总结

1. **组合索引公式**：业务定位字段打头 + `status` 收尾（如 `(dialogue_code, status)`），一条索引同时服务"取数"与"过滤已删除"。
2. **唯一键即幂等**：几乎所有"一主多明细"关系用联合唯一键表达——(task_id, chunk_no)、(parse_task_id, node_no)、(document_id, plan_version)、(topic_code, document_id)、(stage_code, execution_mode)，配合 `INSERT ... ON DUPLICATE KEY UPDATE` 实现可重放、可重复执行的初始化与重建。
3. **状态字段单列索引**：parse_status / index_status / vector_status / task_status 等状态机字段全部单列建索引，服务异步任务扫描与失败补偿。
4. **有意缺失的索引**：MySQL 全库**无外键约束**（业务层维护一致性）；pgvector **暂无 HNSW/IVFFLAT 向量索引**（等 embedding 维度固化后补充）；ES 仅建 mapping 不建额外 settings 定制（分词器回退策略兜底）。
5. **跨库对齐键**：PGVector 表主键直接复用 MySQL chunk 主键；ES chunkId / Neo4j nodeId 也来自 MySQL 主键——关系库是唯一事实源，其他存储都可由它重建。
