## 1. 系统概述

### 1.1 项目定位

本项目是一套企业级 AI Agent 落地系统，核心能力包括：

- **智能对话**：基于 ReactAgent 的多模式问答（开放式提问 / 自动知识问答 / 当前文档问答），支持 SSE 流式输出、会话记忆压缩、推荐追问、全链路阶段追踪（Trace）与检索过程观测。
- **知识库管理**：文档上传解析（Tika）、解析策略智能推荐、切块（结构/递归/语义/LLM）、向量化（PGVector）+ 关键词索引（Elasticsearch）、父块-子块（Parent-Child）双层索引。
- **知识路由**：知识范围（Scope）→ 知识主题（Topic）→ 文档（Document）三层路由配置，配合文档画像（LLM Profile）实现"自动知识问答"模式下的漏斗式知识检索。

### 1.2 模块结构

| 模块 | 说明 | 是否含 HTTP 接口 |
| --- | --- | --- |
| `nexus-agent-business/nexus-agent-business-chat` | **后端业务主服务（单体）**，包含认证、对话、文档管理、知识管理全部接口 | 是 |
| `nexus-agent-common/*` | 通用框架（统一响应 `ApiResponse`、全局异常、Jackson 配置、MyBatis-Plus、分页） | 否 |
| `nexus-agent-redis-tool-framework` / `nexus-agent-redisson-framework` / `nexus-agent-id-generator-framework` | Redis 租约/分布式锁/延迟队列、ID 生成器等框架层 | 否 |
| `ai-example/*` | 教学示例工程（Spring AI、RAG、MCP、Memory 等），独立启动，与主服务无关 | 是（见附录 C） |
| `vue/` | 前端工程（Vue 3），通过 HTTP/SSE 调用主服务 | — |

### 1.3 服务基础信息

| 项 | 值 |
| --- | --- |
| 服务名 | `nexus-agent-business-chat` |
| 默认端口 | `9082`（`server.port`，见 `application.yaml`） |

## 2. 通用约定

### 2.1 统一响应结构

除 SSE 流式接口外，所有接口返回 `ApiResponse<T>`：

```json
{
  "code": 0,
  "message": null,
  "data": { }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| code | Integer | 业务状态码。`0` = 成功；非 0 = 失败 |
| message | String | 提示信息，成功时一般为 null |
| data | T | 业务数据，结构见各接口定义 |

### 2.2 错误码

| code | 场景 | 说明 |
| --- | --- | --- |
| 0 | 成功 | — |
| -100 | 系统错误 | 未识别异常的兜底，message 为"系统错误，请稍后重试!"或具体异常信息 |
| 10054 | 参数校验失败 | `data` 为数组，元素结构：`{ "argumentName": "字段名", "message": "校验提示" }` |
| 业务异常码 | `SuperAgentFrameException` | 返回业务异常自身携带的 code 与 message |
| 401 | 未登录 / token 无效 | **HTTP 状态码同时为 401**，body 形如 `{"code":401,"message":"请先登录后台管理台"}` |

### 2.3 鉴权说明

后台管理接口使用 **JWT Token** 鉴权，由 `AdminAuthInterceptor` 统一拦截。

| 项 | 说明 |
| --- | --- |
| 请求头 | `Authorization: Bearer {token}`（也兼容不带 `Bearer ` 前缀直接传 token） |
| 拦截范围 | `/manage/**`、`/admin/auth/me` |
| 免鉴权接口 | `/admin/auth/login`、`/admin/auth/logout`、全部 `/api/chat/**`、Swagger、Actuator |
| Token 获取 | 调用 `/admin/auth/login`，默认账号 `admin / REDACTED-ADMIN-PASSWORD`（可用环境变量 `NEXUS_AGENT_ADMIN_USERNAME` / `NEXUS_AGENT_ADMIN_PASSWORD` 覆盖） |
| Token 有效期 | 默认 720 分钟（环境变量 `NEXUS_AGENT_ADMIN_TOKEN_EXPIRE_MINUTES`） |
| Token 密钥 | 环境变量 `NEXUS_AGENT_ADMIN_TOKEN_SECRET`，生产环境必须修改 |
| 失效响应 | HTTP 401 + `{"code":401,"message":"<提示>"}`，提示如"请先登录后台管理台"、"后台登录无效，请重新登录" |

### 2.4 预览模式（线上只读）

通过 `NEXUS_AGENT_PREVIEW_MODE_ENABLED=true` 开启后，`PreviewModeInterceptor` 会拦截以下"写操作"接口：

- `/api/chat/stream`、`/api/chat/session/stop`、`/api/chat/session/reset`、`/api/chat/session/summary/rebuild`
- `/manage/document/upload`、`/manage/document/delete`、`/manage/document/strategy/confirm`、`/manage/document/index/build`
- `/manage/knowledge/scope/save`、`/manage/knowledge/scope/delete`、`/manage/knowledge/topic/save`、`/manage/knowledge/topic/delete`
- `/manage/knowledge/document/profile/regenerate`、`/manage/knowledge/document/profile/batch/regenerate`
- `/manage/knowledge/topic/document/save`、`/manage/knowledge/topic/document/remove`

被拦截时 HTTP 状态码为 **200**：

- 普通 JSON 接口返回 `{"code":-100,"message":"<预览模式提示文案>"}`；
- `/api/chat/stream` 返回一个 SSE 帧，内容为 `type=error` 事件。

### 2.5 跨域与请求方法约定

本项目接口几乎全部使用 **POST + JSON 请求体**（包括查询与删除），仅 `/admin/auth/me` 为 GET。OPTIONS 预检请求直接放行。

## 4. 智能对话模块 /api/chat

对应源码：`org.javaup.ai.chatagent.controller.BusinessChatController`

> 该模块全部接口**无需后台登录**。所有查询接口均以 `conversationId`（会话 ID）为主键。

### 4.1 对话流式接口（SSE）⭐ 核心接口

- **URL**：`POST /api/chat/stream`
- **Content-Type**：`application/json`
- **响应类型**：`text/event-stream;charset=UTF-8`（Server-Sent Events 流）
- **说明**：发起一轮对话。服务端执行"会话准备（历史加载/问题改写/子问题拆分/检索规划）→ 知识路由 → 多通道检索 → 生成回答 → 推荐追问"的完整链路，过程与结果通过 SSE 实时推送。

**请求参数（ChatRequestDto）**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| question | String | 是 | 用户提问内容，不能为空 |
| conversationId | String | 否 | 会话 ID。不传或为空时服务端自动生成 32 位 UUID，**前端必须从 SSE 事件中回读该值用于后续追问** |
| chatMode | String | 是 | 对话模式枚举名（大小写不敏感）：`DOCUMENT` 当前文档问答 / `AUTO_DOCUMENT` 自动知识问答 / `OPEN_CHAT` 开放式提问 |
| selectedDocumentId | String | 条件必填 | 仅 `DOCUMENT` 模式必传（必须是"已构建索引、可检索"的文档 ID）；`AUTO_DOCUMENT`、`OPEN_CHAT` 模式**禁止**传该字段，否则报错 |

**校验规则**

- 三种模式的语义：
  - `OPEN_CHAT`：开放式提问，走 ReactAgent + 联网搜索工具（Tavily），不检索知识库；
  - `AUTO_DOCUMENT`：自动知识问答，由知识路由三层漏斗（Scope→Topic→Document）自动定位文档后检索作答；
  - `DOCUMENT`：限定在所选文档内检索作答（RAG）。
- **会话互斥**：同一 `conversationId` 同时只允许一轮对话在执行（Redis 租约 30s、每 10s 续期）。冲突时 SSE 流仅推送一条 `error` 事件："该会话当前正在执行中，请稍后再试"。

**SSE 事件协议**

每个 SSE `data` 帧的负载是一个 JSON 字符串，统一结构：

```json
{
  "type": "text",
  "content": "…",
  "timestamp": "2026-09-12T08:30:00.123Z",
  "conversationId": "6f2c…（有值时才返回）",
  "exchangeId": 1024（>0 时才返回）,
  "count": 5（仅 reference / recommend 事件返回）
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| type | String | 事件类型，见下表 |
| content | String / Array | 事件内容，类型随 type 变化 |
| timestamp | String | 事件产生时间（ISO-8601 Instant） |
| conversationId | String | 会话 ID（**前端据此保存会话 ID**） |
| exchangeId | Long | 本轮问答轮次 ID（用于后续查询轮次详情、检索观测等） |
| count | Integer | 仅 `reference` / `recommend` 事件返回，表示列表长度 |

**事件类型（type）**

| type | content 类型 | 说明 | 典型时序 |
| --- | --- | --- | --- |
| `thinking` | String | 思考/阶段进展文本（如"正在分析问题上下文。"），前端渲染为思考步骤 | 全程多次 |
| `text` | String | **回答正文的增量片段**，前端按序拼接成完整 Markdown 答案 | 高频连续 |
| `status` | String | 状态提示（如"⏹ 用户已停止生成"） | 停止时 |
| `reference` | SearchReference[] | 本次回答引用的来源列表（去重后一次性推送，见附录 A.4） | 回答结束后 |
| `recommend` | String[] | 推荐追问问题列表（最多 3 条，`recommendation-enabled=true` 时生成） | 回答结束后 |
| `error` | String | 错误信息，**收到该事件后流即将关闭，本轮终止** | 任意阶段失败 |

**正常时序示例**

```
data:{"type":"thinking","content":"正在分析问题上下文。","timestamp":"...","conversationId":"6f2c...","exchangeId":1024}
data:{"type":"thinking","content":"已定位知识范围：Java 基础。","timestamp":"...","conversationId":"6f2c...","exchangeId":1024}
data:{"type":"text","content":"在 Java 中，","timestamp":"..."}
data:{"type":"text","content":"HashMap 的默认容量是 16。","timestamp":"..."}
data:{"type":"reference","content":[{"referenceId":"...","title":"…","sourceType":"DOCUMENT",...}],"count":3,"timestamp":"...","conversationId":"6f2c...","exchangeId":1024}
data:{"type":"recommend","content":["HashMap 和 Hashtable 的区别？","..."],"count":2,"timestamp":"...","conversationId":"6f2c...","exchangeId":1024}
```

**请求示例**

```json
// 首轮（当前文档问答）
{ "question": "HashMap 的底层实现原理是什么？", "chatMode": "DOCUMENT", "selectedDocumentId": "1" }

// 追问（复用 conversationId）
{ "question": "那扩容机制呢？", "conversationId": "6f2c9c1e5c7f4b0a9d3e2b8a1c0d4e5f", "chatMode": "DOCUMENT", "selectedDocumentId": "1" }
```

**客户端对接要点**

1. 使用 `fetch` / `EventSource`（需支持 POST 的封装，如 `@microsoft/fetch-event-source`）读取 SSE 流；
2. 每帧解析 `data:` 后的 JSON，按 `type` 分发渲染；
3. 必须处理 `error` 事件（展示 message 并结束本轮）；
4. 用户点"停止生成"调用 `/api/chat/session/stop`，服务端会补发一条 `status` 事件后关闭流；客户端主动断开连接同样会触发服务端停止（`doOnCancel`）。

### 4.4 会话详情

- **URL**：`POST /api/chat/session/detail`
- **说明**：查询会话全量信息，包含全部历史轮次与长期记忆摘要。若该会话正在生成中，返回的当前轮会合并运行时快照（实时已生成的部分答案、状态置为 RUNNING）。
- **请求参数**：同 4.3（`conversationId` 必填）
- **响应 data**：`ConversationSessionView`，结构见附录 A.1。
- **错误**：会话不存在时抛出业务异常（`会话不存在: {id}`）。

**响应 data（ConversationExchangeDetailView）**

**请求参数**：同 4.3（`conversationId` 必填）

**响应 data（ConversationResetVo）**

| 字段 | 类型 | 说明 |

| removedDialogueCount | Integer | 删除的对话消息数 |
| removedExchangeCount | Integer | 删除的问答轮次数 |
| removedCheckpointCount | Integer | 删除的检查点数 |

### 4.8 重建会话记忆摘要

**请求参数**：同 4.3（`conversationId` 必填）

**响应 data（ConversationMemorySummaryView）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| conversationId | String | 会话 ID |
| compressionApplied | boolean | 是否应用了压缩 |
| coveredExchangeId | Long | 已压缩覆盖到的最大轮次 ID |
| coveredExchangeCount | int | 已压缩覆盖的轮次数 |
| compressionCount | int | 累计压缩次数 |
